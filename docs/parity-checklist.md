# Parity checklist

This checklist lists everything actionlint does at the reference commit `011a6d1` that workflint must reproduce for 0.1.0. It covers every check in upstream `docs/checks.md`, the checks that exist only in code, the command-line flags and exit codes, the output formats, `-format` templates, the problem matcher, the config file, project discovery, external tools, and the platform data the checks depend on.

## How to use it

- Pick an item, make its fixtures pass in the conformance suite (ADR 0004), and tick its box in the same pull request.
- An item is done only when every fixture in its row passes. Where the row says "none", add a fixture under the workflint conformance tests in the same pull request.
- Fixture paths are relative to upstream `testdata/`. `examples/x` means `examples/x.yaml` with `examples/x.out`. `projects/x` means the project directory with `projects/x.out`. `ok/x.yaml` must produce no errors. Names ending in `_test.go` are upstream Go tests to port.
- Source references are `file:line` in `.reference/actionlint`, or an anchor in upstream `docs/checks.md`.
- The rule ID column gives workflint's fine-grained rule ID and, in brackets, the actionlint kind it maps to. The conformance suite compares kinds, and the default output prints the rule ID (ADR 0003, ADR 0008). Rows that describe behaviour rather than one message say n/a.
- Rule IDs in this file are proposals until a crate defines their `RuleMeta`. The registry in `workflint-rules` is authoritative for the rules it lists. Renaming an ID there means updating this file.
- A note "Differs" links to an entry in [differences.md](differences.md). For those rows the fixture passes when workflint's output matches the allow-list entry, not the upstream line.
- Messages are byte-identical to upstream unless a row links a difference. `%q` means Go quoting.

Each section of upstream `docs/checks.md` has an `Example input` and an `Output` block that `scripts/check-checks` regenerates. A row is done when the section's example fixture passes and its `Output` block matches workflint's default output for the `Example input`, with the rule IDs in brackets changed and the `^~~~` lines left out, because workflint underlines the whole span ([differences.md#column-units](differences.md#column-units)). An allow-list record of the row's fixture that replaces a line replaces it in the `Output` block too. The conformance test `checks_md::checks.md` runs that comparison for every ticked row. A row here covers the section's example only, so it can be ticked before the rows for its rule IDs above, which cover every fixture of the rule. Sections marked "skip output" need a fixture project instead.
