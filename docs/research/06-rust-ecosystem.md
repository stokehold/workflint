## 1. YAML parsing

### 1.1 Requirements derived from actionlint

actionlint walks a `yaml.Node` tree from go-yaml, not a deserialized struct. Workflint needs:

- **Positions for every key and every value.** actionlint reports `line:col`, and both are 1-based. go-yaml node positions point at the anchor `&a` when present, and at the `|` / `>` indicator for block scalars.
- **Raw scalar text, tag, and style.** actionlint warns about things like `python-version: 3.10` becoming `3.1`, and inspects `run: |` blocks for shellcheck. An eager-typing loader that turns `1.10` into float `1.1` loses this information.
- **Anchors and aliases with names.** actionlint reports `anchor "x" is defined but not used` and `recursive alias "x"`. These checks live in `parse.go` (lines 97–131). It also rejects merge keys: `GitHub Actions does not support YAML merge key "<<"` (`parse.go:335`). GitHub shipped anchor support in Sept 2025 without merge keys; see <https://frenck.dev/github-actions-yaml-anchors-aliases-merge-keys/> and <https://blog.yossarian.net/2025/09/22/dear-github-no-yaml-anchors>.
- **Duplicate keys reported as lint errors with positions,** not as a fatal parse error. This means the loader must see both key events.
- **Comments.** actionlint itself has no inline-disable comments; only shellcheck directives pass through. Workflint's planned `# workflint-disable` style comments need comment text and positions. go-yaml v3/v4 attach Head/Line/Foot comments to nodes.
- **YAML 1.2 core schema semantics.** `on`, `yes`, `no`, `y`, and `off` are strings. YAML 1.1 resolution would turn the `on:` key into boolean `true`, which is the classic serde_yaml 0.8 / PyYAML bug. Workflint only needs schema resolution where it checks types (e.g. `continue-on-error: yes`). Because resolution is done by our own loader, the event parser's YAML 1.1-vs-1.2 origin doesn't matter for the `on:` problem.
- **Pure Rust.** WASM playground plus static musl builds.

### 1.3 Local probe results (behaviour that matters for parity)

Probe input:

```yaml
a: &anc
  x: 1
run: |
  echo hi
b: *anc
```

**libyaml-safer (0-based marks):**
- `MappingStart{anchor: Some("anc")} start=0:3`. The node starts **at `&anc`**, exactly like go-yaml.
- `Scalar{style: Literal} start=2:5`. The block scalar starts **at the `|` indicator**, like go-yaml.
- `Alias{anchor:"anc"}`. The name is present.

**saphyr-parser:**
- `MappingStart(1, None) 2:2`. The node starts at the first key, and the anchor position and name are lost.
- `Scalar(.., Literal) 4:2`. The block scalar starts at the content line, not at `|`.
- `Alias(1)`. The alias carries an id only.
- The `Marker` doc comment says the column is 1-indexed, but we observed 0-based columns.

**saphyr `MarkedYaml` (default early_parse):**
- `ver: 1.10` becomes `FloatingPoint(1.1)`, so raw text is lost unless `early_parse(false)`.
- `on`, `yes`, and `no` stay strings (correct YAML 1.2).
- Alias nodes get the alias span on the outer node, but children keep the anchor's spans. That's acceptable.
- Duplicate keys give `duplicated key in mapping at byte 5 line 2 column 1`, a fatal error.

**granit-parser:**
- `Comment(" actionlint-disable", Right) (1,9)` and `Comment(" full line", Above) (2,0)`. These are exactly what an inline-disable feature needs.

**Implication:** with saphyr-parser, matching actionlint's error positions needs fix-ups:
- scan backwards from the node start for `&name`,
- scan backwards for the block indicator,
- recover anchor names from source text.

These fix-ups are doable but fragile. libyaml-safer gives parity for free because go-yaml *is* libyaml (ported to Go) plus comment handling.

### 1.4 Micro-benchmark (event throughput, actionlint `testdata/**/*.y{a,}ml`)

Corpus: 375 files, 162,507 bytes, 50 iterations, `lto=true, codegen-units=1`, Apple Silicon.

| Parser | Time | Throughput |
|---|---|---|
| libyaml-safer 0.3.0, events | 147.5 ms | 55.1 MB/s |
| saphyr-parser 0.2.2, events | 152.4 ms | 53.3 MB/s |
| saphyr 0.2.2, `MarkedYaml` tree | 219.9 ms | 36.9 MB/s |
| granit-parser 2.0.0, events, comments on | 225.2 ms | 36.1 MB/s |
| yaml-rust2 0.13.0, tree, no marks | 233.8 ms | 34.8 MB/s |
| tree-sitter-yaml 0.7.2 (tree-sitter 0.27.1), CST | 725.1 ms | 11.2 MB/s |

(granit says disabling comments gains ~13%.)

YAML parsing is not the bottleneck at these speeds: about 3 µs per typical workflow file. The event parsers are equivalent in speed. tree-sitter is ~5× slower, and zizmor pays for it *on top of* a second serde parse.

### 1.5 Recommendation

Write **our own loader** that turns parser events into a workflint YAML AST. It should be modeled on actionlint's use of `yaml.Node`. Each node carries:

- span (byte range plus 1-based line/col computed via a line index),
- raw text, style, tag,
- anchor name,
- alias target,
- attached comments.

The loader also:

- keeps duplicate keys,
- marks `<<`,
- resolves scalars lazily with the YAML 1.2 core schema.

For the event backend:

- **Primary: vendor `libyaml-safer` (MIT) as a workspace crate, e.g. `workflint-yaml-events`.** Then port go-yaml's comment scanning (`scannerc.go` / `parserc.go` head/line/foot comment logic) into it. This gives:
  - byte-for-byte position parity with actionlint, which makes porting actionlint's `testdata/err` expectations mechanical,
  - anchor names,
  - pure safe Rust, so WASM works.

  The bus factor is ours either way, because we fork. libyaml is less yaml-test-suite-compliant than saphyr, but it is **exactly as compliant as actionlint**, which is the parity baseline. Track divergences from GitHub's own parser separately, since GitHub doesn't use go-yaml either.
- **Runner-up: `saphyr-parser` 0.2.2**, consumed directly by our loader. This gives better spec conformance and active org maintenance. It costs position fix-ups (anchor and block-indicator offsets, anchor-name recovery from source) and comment extraction. Comments can be recovered by "gap scanning": every byte not covered by a scalar or indicator span is whitespace, an indicator, or a `#` comment.
- **Watch: granit-parser 2.x.** It is the only maintained pure-Rust parser with native comment events and collection styles. Its API settled with 2.0, but it is young (2026-04) and effectively single-maintainer.

Keep the backend behind an internal trait so a swap costs about one module. Run the **yaml-test-suite** and a **differential test against go-yaml/actionlint** in CI.

Use **serde-saphyr 2.0** or **yaml_serde 0.10** only for *our own* config file (`.github/workflint.yaml` / `actionlint.yaml`). serde-saphyr has `Spanned<T>` and snippet errors.

**Writing our own YAML parser from scratch:** not justified. The scanner is the hard part (~5–8k LOC to reach libyaml quality), and the vendored fork gives us the same control.

### 1.6 What other Rust YAML-config linters do

- **zizmor:** two parses per file. `yaml_serde` (libyaml-rs) produces typed models (`github-actions-models`), and on failure falls back to JSON-Schema validation with `jsonschema` 0.58 for messages. tree-sitter-yaml (`yamlpath`) maps findings back to spans and comments. See §2.
- **wrkflw** 0.8.0 (GH Actions validator and local executor, 3.3k stars) and **yamllint-rs** 0.1.4: plain `serde_yaml` 0.9 (deprecated) or `yaml-rust` 0.4. They have no precise key positions, so they are not good precedents.
- **ghalint** (suzuki-shunsuke) and poutine / octoscan / pinact are Go. "ghastly" (Rust, permissions-only) appears abandoned (last push 2025-02).
- **No Rust actionlint port exists** as of today. The closest is zizmor (security-focused).
- **Formatters:** `pretty_yaml` / `yaml_parser` (rowan + winnow, used by dprint) and `yaml-edit` (rowan) build their own lossless CSTs.

## 2. zizmor in depth (closest Rust precedent)

Repo: <https://github.com/zizmorcore/zizmor>, 6.7k stars, v1.31.0 (crates and Homebrew, 2026-10-15), MIT, edition 2024, MSRV 1.97, `unsafe_code = "forbid"`.

**Workspace crates (all published to crates.io at 1.31.0):**
- `zizmor`: CLI and ~45 audits in `crates/zizmor/src/audit/*.rs`.
- `github-actions-models`: serde models for workflows, actions, and dependabot (via `yaml_serde`).
- `github-actions-expressions`: handwritten lexer and parser for `${{ }}`.
- `yamlpath`: tree-sitter-yaml route → span queries, comment extraction, anchor map.
- `yamlpatch`: comment/format-preserving patches, used for auto-fixes.
- `zizmor-sarif`: SARIF 2.1.0 models.
- `subfeature`, `tree-sitter-iter`, `pre-commit-models`, `zizmor-dev`.

**Architecture:** an input registry feeds async audits (tokio, `FuturesOrdered`); online audits use reqwest plus an HTTP cache.

Each finding has a location expressed as a **route** (e.g. `jobs → build → steps → 3 → run`). `yamlpath::Document::query_pretty(route)` resolves the route against the tree-sitter CST into a `Feature` with byte span and line/col (via `line-index`). `feature_comments()` collects comments in the feature's line span. Those comments drive the inline ignores `# zizmor: ignore[rule]`; see `crates/zizmor/src/finding/location.rs`.

Anchors are resolved by a tree-sitter anchor map. Support is still marked **beta**, and zizmor warns once when inputs contain anchors (`main.rs:362`, docs/usage.md#yaml-anchors).

**Other tooling:**
- Rendering: `annotate-snippets` 0.12.16, `anstream`, `owo-colors`.
- CLI: clap 4.6 derive plus `clap_complete`.
- LSP: `tower-lsp-server` 0.23, behind the default `lsp` feature.
- Allocator: `tikv-jemallocator` on non-Windows.
- Tests: insta.

**Distribution** (docs/installation.md, .github/workflows):
- **PyPI** via maturin `bindings = "bin"`. Wheels per platform are built with `PyO3/maturin-action`, and the same wheels feed `pip`, `pipx`, `uvx`, and the pre-commit hook (`language: python`).
- **Homebrew core** (`brew install zizmor`), **cargo** (`cargo install --locked zizmor`), conda-forge, nixpkgs, and Arch.
- **GitHub release binaries** built natively on runners for x86_64/aarch64 Linux gnu, x86_64/aarch64 macOS, and x86_64 Windows msvc. No cross or zigbuild is used. Artifacts are attested with `actions/attest@v4.2.2`.
- **Docker** `ghcr.io/zizmorcore/zizmor`. The image is Chainguard wolfi-base with `uv tool install zizmor==X`, reusing the PyPI build.
- **GitHub Action** `zizmorcore/zizmor-action`: a composite action that pip-downloads a hash-pinned wheel, runs it, and optionally uploads SARIF via `github/codeql-action/upload-sarif`.
- **pre-commit:** `zizmorcore/zizmor-pre-commit` with `language: python`.

**What workflint could reuse:**
- `github-actions-models`: **No, for core linting.** Serde models are lossy (no spans) and fail wholesale on malformed input. actionlint must report *every* malformed key with a position and keep going. Possible uses are as a test oracle, or for `uses:` parsing helpers (`common.rs` `RepositoryUses`, `DockerUses`).
- `github-actions-expressions`: **No for core.** actionlint's expression lexer, parser, and type checker (`expr_*.go`) produce specific error messages and positions that we must reproduce. It is useful as a differential fuzzing oracle.
- `yamlpath` / `yamlpatch`: **not for parsing.** Our AST already carries spans. `yamlpatch` is worth studying (or depending on) if workflint adds `--fix`.
- `zizmor-sarif`: **maybe**, if we add SARIF output (actionlint has no SARIF; users template it).
- **Patterns to copy:** maturin wheel trick for PyPI and pre-commit, native-runner release matrix plus attestations, an action that runs a pinned binary, comment-based ignores scoped to a feature's line span, and an LSP behind a cargo feature.

**What to do differently:**
- Parse once into a span-rich AST instead of serde plus tree-sitter.
- Use a sync pipeline with rayon (no tokio in the hot path).
- Keep the binary offline-first.

**Overlap and competition:**
- zizmor is security-oriented: template injection, unpinned uses, excessive permissions, cache poisoning, impostor commits, and similar.
- actionlint/workflint is correctness-oriented: schema/syntax, expression type-checking, `needs` graph, matrix, runner labels, shellcheck/pyflakes, events and webhook types.
- They overlap on untrusted-input expressions, permissions, deprecated commands, and credentials.

The two tools are commonly run together. Workflint could differentiate on speed, actionlint parity, LSP, SARIF, and inline disables. Expect users to compare on overlapping security checks, so don't try to out-zizmor zizmor.

## 3. Diagnostics rendering

actionlint's default output is custom (`error.go` `PrettyPrint` / `getIndicator`):

```
path:LINE:COL: message [kind]
   |
LL |     source line
   |     ^~~~~
```

**Format details:**
- Colors: yellow path, gray separators, bold message, green indicator.
- The `^~~~` underline width is the run of non-space runes after the column, measured with `runewidth`.
- `-oneline` prints only the first line.

None of the libraries below produces `^~~~` underlines or this exact layout.

| Crate | Version / date | Notes |
|---|---|---|
| **annotate-snippets** | 0.12.16 / 2026-05-06 | rustc's emitter. rust-lang/rust#150032 made the AnnotateSnippet emitter the only `HumanReadableErrorType`. Fast, few deps, rustc/cargo look. Used by zizmor and serde-saphyr |
| codespan-reporting | 0.13.1 / 2025-10-22 | Mature, simple `Files` model, rustc-like look |
| ariadne | 0.6.0 / 2025-10-28 | Pretty multi-label art. Heavier layout, slower, opinionated styling |
| miette | 7.6.0 / 2025-04-27 | Error-handling framework (derive `Diagnostic`, graphical and narratable handlers). The `fancy` feature pulls many deps. 91 open issues, no release in 18 months |

**Recommendation:**
- **Hand-write the default renderer** (~100 lines) for byte-exact parity. Use `unicode-width` 0.2.2 to emulate go-runewidth, and `anstream` 1.0 / `owo-colors` 4.4 for color and NO_COLOR handling.
- Check whether actionlint's `line[:start]` mixes byte and rune columns. Test non-ASCII lines, since this is a likely "better correctness" fix.
- Offer **annotate-snippets** as an opt-in "rich" style with multi-span labels, notes, and help.
- Runner-up: codespan-reporting.
- Avoid miette for output. It is designed for app errors, not high-volume lint output.

## 4. CLI parsing and Go-style flags

Go's `flag` package rules:
- `-flag` and `--flag` are equivalent.
- `-flag=value` and `-flag value` both work for non-bool flags. Bools accept only `-flag` or `-flag=false`.
- No short-flag bundling.
- **Parsing stops at the first non-flag argument.** `actionlint a.yml -color` treats `-color` as a file path.
- `-h` and `-help` print usage.

actionlint flags (`command.go:136–148`): `-ignore` (repeatable), `-shellcheck`, `-pyflakes`, `-oneline`, `-format`, `-config-file`, `-init-config`, `-no-color`, `-color`, `-verbose`, `-debug`, `-version`, `-stdin-filename`. A lone `-` means stdin.

| Crate | Version / date | Go-style support |
|---|---|---|
| **clap** | 4.6.7 / 2026-09-14 | No native single-dash-long (getopt_long_only) mode. Best ecosystem: derive, help, `clap_complete`, `clap_mangen`, env vars |
| lexopt | 0.3.2 / 2026-02-28 | Pedantic minimal parser. You write the loop, so emulating Go exactly is easy, but help and completions are on you |
| argh | 0.1.19 / 2026-03-16 | Fuchsia-style. Only `--long` |
| bpaf | 0.9.28 / 2026-09-17 | Used by biome and oxc. Combinator and derive. No native single-dash-long either |

**Recommendation: clap derive plus an argv pre-pass.** Before `Cli::parse_from`, walk `args_os()`:
- Stop at `--`.
- Optionally stop at the first positional, to match Go exactly. Decide whether to keep Go's stop-at-first-positional or allow intermixing. Allowing intermixing is a compatible superset except for file names starting with `-`.
- Rewrite any token `-name` or `-name=value` to `--name` / `--name=value` when `name` (length > 1) is a known long flag. Generate the set from `Cli::command().get_arguments()`.
- Leave `-` alone.
- Map `-help` to `--help`.

Also:
- Accept `--flag=false` for bools via `ArgAction::Set` with `num_args(0..=1)`, `default_missing_value("true")`, and a bool value parser.
- Keep `--` long forms in help output.
- Use `ArgAction::Append` for repeatable `-ignore`.

Runner-up: lexopt, if we want 100% Go-flag semantics and are willing to hand-write help text (actionlint's help is custom anyway).

## 5. Go `text/template` for `-format`

actionlint uses `text/template` with these extra functions (`error.go:262–282`):
- `json`: `json.NewEncoder`, so **HTML-escaping `<`, `>`, `&` as `\u003c` etc.** with a trailing newline,
- `replace` (`strings.NewReplacer`),
- `toPascalCase`,
- `getVersion`,
- `allKinds`.

It also calls `unescapeBackslash(format)`.

Data is `[]*Error` with fields `Message`, `Filepath`, `Line`, `Column`, `Kind`, `Snippet`, and `EndColumn`. JSON tags are `message`, `filepath,omitempty`, `line`, `column`, `kind`, `snippet,omitempty`, and `end_column`. Templates use `range`, `$var`, `if`, `len`, `printf`, pipelines, and so on (see docs/usage.md).

**gtmpl** 0.7.1 (fiji-flo/gtmpl-rust, MIT) is the only Rust implementation:
- Last release 2021-08-06, last push 2022-03-30.
- Self-described "work in progress": no `html` or `js` functions, `printf` "not fully stable", no complex numbers.
- The lexer predates Go 1.18's `break` / `continue`.
- Values go through `gtmpl_value::Value`, and functions are `fn(&[Value]) -> Result<Value, _>`.
- Builtins present: `eq`, `ne`, `lt`, `le`, `gt`, `ge`, `len`, `and`, `or`, `not`, `urlquery`, `print`, `println`, `printf`, `index`, `call`.

**Recommendation: implement our own subset** (~1.5–2.5k LOC). It needs:
- lexer with trim markers `{{-` / `-}}`,
- parser for actions, pipelines, variables, `if` / `else if` / `range` / `with` / `define` / `template` / `block` / `break` / `continue`,
- executor over a small `Value` enum (string, int, bool, list, map/struct with ordered fields, func).

Implement Go's `fmt` `%v` / `%d` / `%s` / `%q` semantics for the verbs users actually use. Mirror Go's error messages for parse errors where tests depend on them.

Implement the `json` func with **serde_json plus a custom `Formatter`** that escapes `<`, `>`, `&`, U+2028, and U+2029 like Go, keeps struct field order, and appends `\n`.

Then port actionlint's `testdata/format` and `error_test.go` cases as golden tests.

Runner-up: vendor gtmpl and patch it (add `break` / `continue`, fix `printf`). That gets us running sooner, but we'd own a 2021 codebase anyway.

## 6. Core libraries

**Parallelism:**
- **rayon** 1.12.0 (2026-04-14). Lint files in parallel with `par_iter`, and sort errors deterministically afterwards (actionlint's `compareErrors`).
- The shellcheck/pyflakes subprocesses dominate actionlint's runtime. actionlint already runs them concurrently with a semaphore (`process.go`). Port that as a bounded worker pool (`std::process` plus a rayon scope or a dedicated thread pool) and batch scripts per process where possible. This is where "much faster" will mostly come from, alongside avoiding Go's per-file overhead.
- Gate rayon behind a feature for WASM.

**Regex:**
- **regex** 1.13.1 (2026-07-15). Its RE2-like syntax is a good fit for `-ignore` and config `ignore` patterns.
- **Parity gotcha:** Go's `\d`, `\w`, `\s`, and `\b` are **ASCII**. Rust's are **Unicode** by default. Parse user patterns with `regex-syntax` and rewrite Perl classes to ASCII (`(?-u:\d)` is allowed in `&str` regexes because it can't match invalid UTF-8), or document the difference.
- Compile built-in regexes once with `std::sync::LazyLock`.
- `fancy-regex` 0.19.2 is not needed: no lookaround in RE2.
- `regex-lite` is an option for the WASM size budget.

**Globs:**
- actionlint only **validates** GitHub filter patterns (`glob.go`, with its own scanner and column-precise errors; `rule_glob.go`). Port it 1:1.
- For config `paths:` matching (doublestar semantics), use **globset** 0.4.20 (2026-08-04, ripgrep) with `literal_separator(true)` and always-`/` separators. Biome, ruff, and zizmor (`ignore`) all use it.
- Runner-up: **wax** 0.7.0 (2026-01-29). It is stricter and more featureful but has a smaller user base.

**Interning and arenas:**
- Workflow files are small and the work is per-file, so borrowed `&'src str` slices into the source buffer and `compact_str` 0.10.0 cover most needs.
- Context and property names in the expression type checker are a good fit for a per-file **string-interner** 0.20.0 (2026-04-30) if profiling shows hashing or alloc cost.
- **lasso** 0.7.3 (last 2024-08) has a `ThreadedRodeo` but is quiet.
- **bumpalo** 3.20.3 (2026-05-22) is an option for the expression AST. typed-arena 2.0.2 (2023) is stable but stagnant.
- Avoid a global multi-threaded interner.

**Hashing:**
- **rustc-hash** 2.1.3 (FxHash v2): used by rustc, ruff, oxc, and biome. Deterministic, and needs no `getrandom`, which helps WASM.
- foldhash 0.2.0 (hashbrown's default) is the runner-up.
- ahash 0.8.12 (last 2025-05) is not needed.

**JSON:**
- **serde_json** 1.0.154 (2026-10-11) for output, SARIF, and the LSP.
- simd-json 0.18.1 and sonic-rs 0.5.10 are pointless at this scale. sonic-rs is also SIMD/arch-specific, which is bad for WASM.
- actionlint's big embedded datasets (`popular_actions.go`, `all_webhooks.go`, `availability.go`) should be **code-generated into Rust statics** (`match`, `phf`, or sorted arrays) by an `xtask`, not parsed at startup.

**Case-insensitive maps:**
- GitHub contexts, env, and matrix keys compare case-insensitively.
- Store **ASCII-lowercased keys** (`to_ascii_lowercase`) in `FxHashMap` / `IndexMap` and keep the original spelling for messages.
- Note that Go's `strings.ToLower` is Unicode-aware. Choose deliberately and test non-ASCII keys.
- Runner-up: `unicase` 2.10.0.

**Also useful:**
- `indexmap` 2.14.2 (ordered maps; keys in source order)
- `line-index` 0.1.2 (rust-analyzer; byte ↔ line/col)
- `memchr` 2.8.3
- `ignore` 0.4.33 (gitignore-aware walking)
- `mimalloc` 0.1.52 or `tikv-jemallocator` 0.7 (cfg-gated)
- `camino` (UTF-8 paths)
- `cron` parsing: port `robfig/cron` semantics or find a 5-field cron crate. This is a separate item, not covered here.

### 7.3 npm

Patterns observed in the registry (2026-10-15):

| Package | Pattern | postinstall | npm attestations |
|---|---|---|---|
| `@biomejs/biome` 2.5.15 | `optionalDependencies` on 8 `@biomejs/cli-<os>-<arch>[-musl]` packages (with `os`, `cpu`, `libc` fields) + `bin/biome` JS shim | none | yes |
| `oxlint` 1.88.0 | 19 `@oxlint/binding-*` packages | none | yes |
| `turbo` 2.11.8 | 6 `@turbo/*` packages | none | yes |
| `esbuild` 0.28.2 | optionalDeps + `postinstall` fallback/validation | yes | yes |
| `@axodotdev/dist` 0.33.0 (dist's npm installer output) | single package, `postinstall` downloads from GH Releases, uses `detect-libc` | yes | no |

**Recommendation:** use the **biome pattern**:
- `workflint` holds a JS shim that resolves `@workflint/cli-${platform}-${arch}[-musl]` via `require.resolve` and execs it with `child_process.spawnSync` and `stdio: 'inherit'`.
- Each platform package sets `os`, `cpu`, and `libc` (`libc` lets npm pick the musl vs glibc package).

Postinstall downloads break in several places:
- pnpm ≥10 doesn't run dependency lifecycle scripts by default,
- Bun blocks untrusted lifecycle scripts,
- `npm ci --ignore-scripts`,
- offline and corporate mirrors.

Publish from GH Actions with **npm Trusted Publishing**. It uses OIDC, needs npm CLI ≥ 11.5.1 and `id-token: write`, and creates provenance automatically. Classic tokens were revoked in Nov 2025, and granular write tokens are capped at 90 days (<https://github.blog/changelog/2025-09-29-strengthening-npm-security-important-changes-to-authentication-and-token-management/>).

Note: the npm name `actionlint` belongs to an unrelated 2022 package (2.0.6).

### 7.4 Homebrew, Scoop, winget, and others

- **homebrew-core** (<https://docs.brew.sh/Acceptable-Formulae>, <https://docs.brew.sh/Package-Acceptance-Policy>):
  - needs a stable tagged release,
  - must build from source (for us, `cargo install`-style via `std_cargo_args`),
  - should have no self-update,
  - notability: ≥30 forks, ≥30 watchers, or ≥75 stars, and **≥225 stars (or 90 forks/watchers) if the owner self-submits**,
  - the repo must be ≥30 days old.

  So: **start with a tap** (`workflint/homebrew-tap`, auto-updated by dist), then go to core once notable. Someone else submitting at 75 stars is typical. actionlint itself ships a Cask in-repo plus a formula in core (1.7.12). zizmor is in core.
- **Scoop:** our own bucket or a PR to `ScoopInstaller/Extras`. Main bucket for workflint is 404, so it's free.
- **winget:** `vedantmgoyal9/winget-releaser` (pushed 2026-10-13) or `Komac` (pushed 2026-10-15) to PR `microsoft/winget-pkgs` on release.
- Later: conda-forge, nixpkgs, AUR. Community-maintained ones will appear, as they did for zizmor.

### 7.5 PyPI (strongly consider)

maturin `bindings = "bin"` publishes the Rust binary as platform wheels. This gives `pipx`, `uvx workflint`, and above all the **pre-commit `language: python`** hook with prebuilt binaries. Both zizmor and ruff use this. PyPI Trusted Publishing plus PEP 740 attestations are available.

### 7.6 Docker

- Static musl binary in `FROM gcr.io/distroless/static-debian12:nonroot` (or `scratch` plus CA certs, if no network is needed).
- actionlint's official image bundles **shellcheck** (from `koalaman/shellcheck-alpine`) and **py3-pyflakes** on Alpine. Ship a `:full` variant like that for parity. A minimal image would silently skip those checks.
- Publish to `ghcr.io/<org>/workflint` and Docker Hub, multi-arch via `docker buildx`.
- Sign images with **cosign keyless** and/or `actions/attest` with `push-to-registry: true`.

### 7.7 pre-commit and GitHub Action

**pre-commit:** provide these hooks.
- `workflint` with `language: python`, backed by PyPI wheels, so no Rust toolchain is needed. Avoid `language: rust` (compiles from source, minutes).
- `workflint-docker` with `language: docker_image`.
- `workflint-system` with `language: system`.

These mirror actionlint's `.pre-commit-hooks.yaml` (`golang`, `docker_image`, `system`). Use `files: ^\.github/workflows/` and `types: [yaml]`.

**GitHub Action:** a composite action that downloads a pinned, checksum- or attestation-verified release binary for `runner.os` / `runner.arch`, caches it in the tool cache, and runs it. Default to `-format` emitting `::error file=…` workflow commands, or a SARIF upload via `github/codeql-action/upload-sarif`. zizmor-action does the same with a hash-pinned wheel.

Also publish a problem matcher (actionlint documents one).

### 7.8 Signing and provenance

- **GitHub artifact attestations:** `actions/attest@v4.2.2` / `actions/attest-build-provenance@v4.2.2` (2026-08-06), built in to dist. Verify with `gh attestation verify --repo <org>/workflint`.
- **npm provenance:** automatic with Trusted Publishing.
- **crates.io and PyPI Trusted Publishing** (PyPI also gets PEP 740 attestations).
- **cosign** for container images.
- **macOS:** notarization/codesign isn't required for CLI tarballs fetched by curl/brew, though quarantine affects browser downloads. dist supports macOS signing if wanted later.
- **Windows:** dist 0.33's Azure Artifact Signing, x64 only.
- **Install script:** dist's `curl -LsSf …/workflint-installer.sh | sh` verifies checksums. Document `gh attestation verify` for the paranoid.

## 8. WASM playground

Toolchain:
- **wasm-bindgen** 0.2.129 (2026-09-25). It moved to the `wasm-bindgen` GitHub org after the rustwasm WG sunset in 2025.
- **wasm-pack** 0.15.0 (2026-05-15), now at `wasm-bindgen/wasm-pack`.
- `tsify` 0.5.8 (2026-08-23) for TS types of the diagnostics.
- `serde-wasm-bindgen` 0.6.5 (2024-02, stable).

actionlint already has a Go/WASM `playground/` to replace.

**Compatibility of the recommended stack:**
- **Fine:** libyaml-safer / saphyr / granit (pure safe Rust), regex (or regex-lite to save ~100–300 KB), serde_json, rustc-hash, indexmap, compact_str, and our template engine.
- **Gate off:**
  - rayon. Optionally use `wasm-bindgen-rayon` 1.3.0 (2024-12), which needs SharedArrayBuffer and COOP/COEP headers. Not worth it for a playground.
  - shellcheck/pyflakes subprocesses: unavailable, so show a notice.
  - filesystem/project discovery,
  - allocators (jemalloc/mimalloc),
  - `std::time::Instant`, which panics on `wasm32-unknown-unknown`; use `web-time` if timing is needed.
- **Avoid:**
  - tree-sitter. Its C runtime and grammars need a wasm sysroot or the `tree-sitter-c2rust` fork for `wasm32-unknown-unknown`. This is one more reason not to follow zizmor's CST approach.
  - foldhash/ahash random seeding, which pulls `getrandom`. The `wasm_js` backend config is needed if you use them.

Keep the core as a `no-IO` library crate (`workflint-core`). Put the CLI, LSP, and WASM front-ends on top.

## 9. LSP

| Crate | Version / date | Notes |
|---|---|---|
| **lsp-server** | 0.10.0 / 2026-10-08 | rust-analyzer team. Synchronous (crossbeam channels), minimal, no tokio. Used by **ruff** (with `gen-lsp-types` 0.11.0, 2026-07-28, ruff's maintained fork of lsp-types) |
| tower-lsp-server | 0.23.0 / 2026-09-11 | Community fork of tower-lsp. Async/tokio, ergonomic trait. Used by **zizmor** (0.23), **biome** (0.23), and **oxc** (0.24.0-rc.1) |
| tower-lsp | 0.20.0 / 2023-08-11 | Original. Unmaintained (last push 2024-08). Don't use |
| lsp-types | 0.97.0 / 2024-06-04 | Stale. Prefer gen-lsp-types or what tower-lsp-server re-exports |

**Recommendation:** **lsp-server + gen-lsp-types**. Linting is CPU-bound and sync, so it fits rayon and a debounce loop, and avoids pulling tokio into the binary. Ship it behind a cargo feature (`workflint lsp` / `--lsp`), as zizmor does.

Runner-up: tower-lsp-server, if we later need async (e.g. fetching remote reusable-workflow or action metadata).

Design the core API so the LSP can re-lint one file from an in-memory buffer and map our spans to LSP UTF-16 positions. `line-index` 0.1.2 supports UTF-16 conversion.

- Runner-up: **libtest-mimic** 0.8.2 (2026-03-16) for custom runners. It is the lower level that datatest-stable builds on.
- Run with **cargo-nextest** 0.9.148.

**Conformance:**
- yaml-test-suite for the YAML backend.
- **Differential testing against Go actionlint.** Run both over the actionlint corpus plus a large real-world corpus (e.g. the top-N GitHub repos' workflows, as zizmor's `crater-tests` / actionlint's `testdata/realworld` do) and diff the `-format '{{json .}}'` output.

**Micro-benchmarks:**
- **divan** 0.1.21 (last 2025-04, quieter) or **criterion** 0.8.2 (2026-02-04, now criterion-rs org).

- Recommend divan for ergonomics; criterion if you want its statistics and HTML reports.

**End-to-end:**
- **hyperfine** 2.0.0 (released 2026-10-07): `hyperfine --warmup 3 -N 'actionlint' 'workflint' --export-json`.

- Benchmark on large monorepos with hundreds of workflows and on single-file stdin. Go's startup is ~ms, so single-file wins come from not spawning shellcheck per step.

**Fuzzing:**
- **cargo-fuzz** 0.13.2 (2026-06-09). Targets: YAML loader (no panics; spans within bounds), expression lexer/parser/type-checker, glob validator, template parser.
